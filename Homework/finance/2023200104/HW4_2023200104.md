# Team2 租金/售价模型代码审阅与优化建议

## 概览

- 两套流水线（租金/售价）完整覆盖清洗、特征工程、Yeo-Johnson 变换与 K-Means + 线性回归评估。
- 结构清晰，但存在会影响指标可信度与泛化能力的关键问题。
- 以下给出5条优化建议。

## 1. Yeo-Johnson 逆变换错误（目标恢复不正确）

- 问题：自定义 `inverse_yeojohnson` 未按分段公式实现，也未处理 `lambda=0` 与负值分支，导致把模型输出从 YJ 空间还原到原价空间时出现系统性误差。
- 后果：
  - 线下 MAE 指标与真实价格的绝对误差不匹配，模型优劣比较失真。
  - 测试集提交价格整体偏离真实分布，极端值可能被错误拉伸或截断为零
- 建议：
  - 训练阶段对目标 `y` 使用 `PowerTransformer(method='yeo-johnson', standardize=False)` 拟合并保存变换器；预测与评估均用 `inverse_transform` 做反变换。
  - 若需手写，按官方分段逆函数实现：当 `lambda!=0` 且 `x>=0` 用 `(x*lambda+1)^(1/lambda)-1`，当 `lambda!=2` 且 `x<0` 用 `1-(1-x*(2-lambda))^(1/(2-lambda))`，当 `lambda=0` 或 `lambda=2` 用相应极限式；同时对数值下溢用极小正数防护。
  - 在自定义 `make_scorer` 中先对 `y_pred` 与 `y_true` 做 `inverse_transform`，再计算 MAE；测试集导出同样走统一逆变换路径。

## 2. K-Means 只评估单点 K=200

- 问题：聚类超参搜索退化为单点，后续 Lasso/Ridge 直接复用该 K 值，没有与其他 K 或“无聚类”基线对比。
- 后果：
  - 以 200 类 OHE 引入高维稀疏特征，可能放大噪声或过拟合。
  - 无法证明 K=200 是最优选择，空间信号表达可信度不足。
- 建议（更具体）：
  - 网格搜索 `K∈{50,100,150,200,300}` 并记录 `MAE-K` 曲线；选择拐点或最优点。
  - 使用空间分组交叉验证（如按城市/区县分组的 GroupKFold 或按经纬度网格分块的 Block CV）降低空间泄漏。
  - 与“无聚类”基线对比：直接对 `lon/lat` 构造样条/RBF特征或采用 geohash/quadkey 网格编码；若保留聚类，优先用目标编码替代 OHE 以降维。

## 3. 链式赋值与 `inplace=True`的问题

- 问题：大量使用 `Series.fillna(..., inplace=True)`、`clip(..., inplace=True)` 与链式赋值触发 FutureWarning/PerformanceWarning，未来版本可能不生效或只作用于副本。
- 后果：
  - 清洗与截断操作可能“悄然未生效”，产生不可复现结果。
  - DataFrame 高度碎片化，带来性能下降与内存浪费。
- 建议（更具体）：
  - 统一改为非 `inplace` 写法：`df[col]=df[col].fillna(val)`、`df[col]=df[col].clip(lower=...,upper=...)`、`df.loc[idx,col]=...`；批量新增列用 `pd.concat([...],axis=1)` 一次性合并。
  - 编写简短检查脚本，搜索并替换所有 `.fillna(..., inplace=True)` 与 `.clip(..., inplace=True)`，消除链式赋值。

## 4. 核心特征定义（房龄/建筑年代/交易时间）

- 问题：房龄以当前年差 `2025-建筑年代` 计算而非交易时点；`parse_build_year` 对多年份取均值不合理；“绿 化 率/容 积 率/物 业 费”等别名未统一。
- 后果：
  - 年龄与时点错配，系数与解释偏离真实市场节奏。
  - 口径混乱导致统计与分组填充出现错配，模型学习到错误信号。
- 建议（更具体）：
  - 房龄改为 `df['房龄']=df['交易时间'].dt.year-建筑年份`（缺交易时间时用上次交易或注册日期兜底），并对负值截断为零。
  - 多年份场景取最早“建成年份”，另增“翻修年份/最近改造年”作为备选特征。
  - 在清洗开头统一 `rename`：`{'绿 化 率':'绿化率','容 积 率':'容积率','物 业 费':'物业费'}`，消除重复名与空格变体。

## 5. 类别/文本特征治理与租期解析（去重、规范、降维）

- 问题：供暖的二值化重复展开；租期解析依赖大量经验替换（“以上/以内”线性推断）；读取售价数据出现混合类型警告。
- 后果：
  - 重复列与长尾类别带来噪声与训练开销，削弱有效信号。
  - 租期映射产生系统性偏差，影响租金的时长敏感性。
  - 类型不一致导致数值计算与缺失填充出错。
- 建议（更具体）：
  - 去重并集中维护类别展开映射；对长尾类别采用频率或目标编码以降维，并配合更强正则化。
  - 统一正则解析租期：识别“X个月”“X~Y个月”“N年”“N年以内/以上”，将“年”转为“月”，范围取中位；“以上/以内”用区间期望（以上：下界=X，上界用历史分布上分位；以内：上界=X，下界为0）。
  - `read_csv` 显式 `low_memory=False` 并为关键列指定 `dtype`，数值列统一强转为 `float`；文本特征优先保留“是否存在”和“长度”两项轻量指标，避免高成本 NLP。
